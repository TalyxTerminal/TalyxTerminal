# Market

Market is the foundation for every TalyxTerminal module that consumes market data ([Chart](../chart/README.md), [Quant](../quant/README.md), [Agent](../agent/README.md)): instrument identity and search, sources and ranking, local storage, history and live data, research data, trading terms and professional materials. Consumers say only which instrument, which kind of data and which period they need; where it comes from, how it is connected and how it is stored is Market's job. The public interface is defined by [public/contract.json](public/contract.json).

Design references: AmiBroker with Norgate (a local database, topped up nightly), OpenBB providers (configure credentials once, one data model), TradingView (adjusted by default on charts, delayed-data markers).

## Principles

- **Correct numbers come first.** Only unadjusted prices are stored, together with corporate actions and adjustment factors; adjustment is applied on read. Dividends and splits never rewrite stored prices, and exported files are unaffected. No survivorship bias: delisted stocks and delisted coins have prices if a source has them, and nothing is invented if not. Units, time zones and day boundaries are unified across sources: crypto days split at UTC (OKX daily bars are requested as `1Dutc`, not Hong Kong time); stocks use the exchange's local trading day, with a daily bar's `time` at local midnight and its `closeTime` at the actual close.
- **Local first; draw now, fill later.** Every read reads the local store; the network only fills what is missing, and stored data stays viewable offline. A read fills gaps with at most 50 source requests; beyond that it returns `fill_too_large` and the work belongs to a fetch job. Live sessions (charts) do not wait for the whole range: when the local store lacks the latest bar, only the latest page is requested first and sent; the rest is filled in the background and then replaces the window once (see [Live](#live)).
- **One source per series.** For each "market × data kind", Market ranks sources by their declarations and picks the best; one series is never stitched from two sources by year or by instrument.
- **Works without keys; better with them.** Free sources (Yahoo, the exchanges, Baostock, the HKEX securities list, the Nasdaq symbol directory, SEC, CoinGecko) work out of the box. Adding a key for Alpaca, Sharadar, Tushare and others switches the ranking automatically, with no change for consumers.
- **Stable.** TalyxTerminal itself causes no disconnects. Planned disconnects (Binance every 24 hours) connect the new link before dropping the old. Unexpected disconnects are reconnected and filled by Market; consumers see `recovering` and then `live` and never need to reopen (`connecting`, before the first connection, is not a disconnect). All sources dropping at once is treated as the user's network; a single source dropping says which one, why, and when it will retry.

### Instrument and time notation

| Input | Instrument |
| --- | --- |
| `AAPL`, `600519.SH`, `0700.HK` | Local listing code |
| `US:DASH` | A code on a specified market |
| `USDCNY=X` | USD/CNY exchange rate |
| `binance:BTC/USDT`, `okx:BTC/USDT:USDT` | Spot or perpetual on a specified exchange |
| `instrumentId` | One unique instrument, including delisted ones and reused codes |

`start` and `end` are both inclusive. With only a date, stocks use the exchange's local trading day and crypto uses UTC. `read_data` and code-based export adjust stocks for splits only by default. When moving instruments between data directories, a module can pass the full saved record to `instruments.get` as `records`, receive the local id, and keep reading by id.

## Panel

Market has its own panel with two tabs:

- **Library** (local data). Grouped by market and data kind, one row per group: number of instruments, rows, date range, gaps, source, size. Running fetch jobs are at the top and can be cancelled; interrupted jobs can be resumed. Selecting a row shows details: a coverage timeline (one row per year, one cell per month; one row per decade when the span exceeds 16 years) and fillable gaps (ranges the source confirms it does not have count as covered), corporate actions and adjustment factors, code history, the latest raw rows (adjustment switchable), and **Open in Chart** (optionally at a given day). **Get data** fetches by historical index membership or a single instrument × data kind × period, estimating the size first and comparing it with free disk space. Import loads a folder; Export writes the selected data to a folder (Parquet or CSV, optionally adjusted).
- **Sources.** One row per source with its status and an on/off switch. Expanding a row configures the key and settings (keys are write-only and show only set / not set), tests the source, shows what it provides (the "Gives" table) and which data currently uses it, and can delete that source's local data. **Test all** tests one sample per source and returns within 10 seconds. A paid source whose subscription has lapsed counts as unavailable, and Market falls back to the next best. Sources and keys can also be configured on the Market page of the Settings window. Keys are global, not per workspace, and both places edit the same values.
- The panel is public (`main`); other modules and the Agent open it through the platform. Open targets that go to a specific series, source or job are not supported yet; they all land on Library.

The panel talks to the backend only through the private route `/m/market/panel` and the public contract. Everything the Agent can do is in the public contract; the panel has no back door.

## Instrument identity and search

- **Stocks, ETFs, indices** (`identityVersion` 2): ids are issued by Market, contain no source, and do not change with renames or code changes. Codes are recorded by period (the `codes` table); when one code belongs to different companies over time, they are separated by period. Where a source uses its own notation, Market converts (`BRK.B` → Yahoo `BRK-B`, `600519.SH` → `600519.SS`, `00700.HK` → `0700.HK`). An id can be handed to another data directory; if that directory already has the same instrument (same current code and listing date), it answers with a redirect.
- **Crypto** (`identityVersion` 1): exchange plus contract; the id is a content digest. When an exchange reuses a code (Binance LUNA/USDT before and after 2022-05-13 are two different coins), the instrument is split by time: the old segment carries `retiredAt`, and the split point is frozen the first time the code is read.
- **Rename continuity.** Rename records from sources (Alpaca `name_change`, from 2017-04) are applied from newest to oldest: the old code's segment merges into the current instrument, and searching for the old code finds the current instrument, marked with the former code and the date it was used until. Without an Alpaca key, the instrument before and after a rename is two instruments. An A-share code change (000043 → 001914) is treated as one instrument when both list on the same day and the daily bars for the 20 days before the change are identical; the old id redirects to the new one.
- **Listings.** US stocks use the official Nasdaq symbol directory, A-shares use Baostock (including delisted), Hong Kong uses the HKEX list (stocks, ETPs and REITs only), crypto uses each exchange's catalogue. When a listing date is unknown, the code segment starts when the code is first seen and moves earlier once older bars are read.
- **Search** ranks by current code, former code, code prefix and name; searching AAPL returns one result. Chart display forms (BTCUSDT, BTCUSDT.P) are also found; `exchange:code` (OKX:BTCUSDT.P, as in TradingView) searches only that exchange. Yahoo is asked only when nothing in the local listings matches (the same query at most once in ten minutes), so every keystroke is answered locally within tens of milliseconds. English names from search answers never replace the name in the exchange listing (searching 茅台 still works).

## Sources and ranking

- Official and third-party sources use the same extension point, `market.data_source`. A source declares what it provides in its manifest (markets, data kinds, timeframes, depth, live support, whether a key is needed, settings). Market ranks and admits sources from these declarations plus the results of actual requests; there is no per-instrument allow-list.
- **Downloadable files and APIs follow one plan** (`planner.py`). Sources declare their files per timeframe (`archives`: monthly or daily, date range, publication delay, the time zone days are split in, price bases); the API layer declares depth and rows per page (price bases that page differently are declared separately as `basisRows`; OKX mark and index price: 100). URLs and parsing stay in the source. Market fills every source in the order "monthly file → daily file → API": files are used when the API cannot reach that far, or when a file saves more than one page of requests. When a file has nothing, the next layer is used (monthly to daily, daily to API; delisted contracts the API no longer serves fall back to files). Days with no rows in a monthly file are asked from daily files. The API part is split into segments run in parallel according to how many concurrent requests the source allows. Each answer is stored as it arrives. Sources with files today:
  - Binance: spot and futures bars including mark price, index price and premium index; funding; open interest and long/short ratio. Futures data older than a month comes from files, which include delisted contracts and the zero-volume filler rows needed to detect reused codes.
  - Gate: monthly files for spot and USDT perpetuals, spot 1-minute and 5-minute to 2024-03, funding.
  - OKX: 1-minute bars for spot from 2020-01 and perpetuals from 2021-09, as monthly and daily files split at UTC+8, and monthly funding files.
  - Bitget has no publicly documented download files and uses the API only.
- Exchange request pacing is controlled per endpoint by the SDK's exchange request queue, using the per-exchange limit table Market supplies (`exchange_limits.py`; OKX uses a 2-second window per endpoint, checked against the official documentation). For crypto sources Market only limits concurrency. Background session fills run one priority level below reads, and fetch jobs one level below that.
- Ranking (for the same market × data kind, the first available source wins): US daily: Sharadar > Yahoo (compared on depth); US intraday: Alpaca (from 2016) > Yahoo (1-minute about 30 days, 1-hour about two years); A-share daily: Tushare (whole market per date in one request) > Baostock. IB and Futu provide live and recent history only to account holders and are not used as bulk historical sources for research. Turning a source off refetches the affected stored series from the next source as a batch (a background job; each series is swapped only once fully fetched, so no series ever holds rows from two sources), and open charts receive one replace.
- Settings and keys are declared by the source and handed to it to store through `write_source configure` (keys live in the platform's secret service). The Agent can change only non-secret settings.
- **One network exit** (`backend/network.py`): every request goes through the user's proxy (a regular proxy or TUN mode both work; with `ProxyEnable=0` it connects directly). IB and Futu connect only to the local machine. Source refusals are reported as they are (for example HTTP 451); regional blocks are for the user to solve by switching nodes. Market does not switch sources automatically.
- Conformance check (`write_source test`): description, timeframes, columns, ordering, time unit (nanoseconds), window, paging, errors; each source with its latency, listing only what failed.

## Storage, reads and adjustment

- Each series is a directory: time-partitioned Parquet plus a `pointer.json` (source, `revision`, fetched ranges, "source has none" ranges and "unavailable" ranges). "Source has none" is recorded only when the source confirms the range is empty. A range that was asked for, could not be supplied by any layer and was not confirmed empty is recorded as `unavailable`, with the next retry time and the reason: a file not yet published waits until it is due; a late file waits 6 hours; a refusal (such as HTTP 451) waits 1 hour. Until then, reads do not ask again and the gap states the reason (`unavailable`, `retryAt`, `problem`); fetch jobs started by the user or the Agent ask again immediately. A range no layer can reach (after Gate's last spot 1-minute file and before the API's depth) is also `unavailable`, with no retry time. Corporate actions and factors are one JSON per instrument. Writes go to a temporary file and are then renamed; on Windows, when a rename or read is blocked by another handle (a reader, antivirus, indexing), Market waits briefly and retries.
- **Publication cutoff.** Each series has a publication cutoff: the close plus the source's declared publication delay (Yahoo daily: 4 hours, chosen conservatively from the CSI finalization time for US daily bars; not measured on Yahoo). Reads, fetches, live data, coverage and export all follow it: bars before their cutoff are not fetched or stored as final; when a source has not yet provided the latest bar, it is not recorded as "source has none" and is asked again next time. Coverage reports the cutoff (`publishedThrough`); Quant's "Latest close" uses it.
- **Inconsistent bars.** When a source's high and low do not contain the open and close, that range is requested once more. If still wrong, open and close are kept as given and high and low are widened just enough to contain them; the source's original values are recorded on the series and are readable in coverage (`local.repaired`).
- **Intraday bars sit on the exchange's own grid** (the open and close times from `bar_times`). Rows a source gives after the last slot of a session on the same day are the closing auction and are merged into the last slot: `closeTime` remains the close and the closing price is the auction price (Hong Kong's 16:08 row merges into 15:59; Yahoo puts the last half hour of a US half day at 13:00 with volume 0, which becomes the 12:30 bar). Other off-grid rows are rejected. Yahoo aligns Hong Kong 60m afternoons on :30, so Hong Kong 1h is aggregated from 15m instead and covers only 60 days.
- A-share calendar: `exchange_calendars` hard-codes A-share holidays year by year. Market adds, in `calendars.py`, years the State Council has announced but the library does not yet include (currently through the end of 2027); each year must be added after its announcement.
- Only base timeframes are stored; other timeframes are aggregated on read, with the same aggregation function for history and live (a daily bar aggregated from 1,440 one-minute bars matches the source's daily bar field by field).
- For 24/7 markets, daily, weekly and monthly bars are aggregated from intraday bars that divide a day evenly when the source has no daily bars (HTX has only intraday bars). Aggregated bars of a day or longer close only at the end of their period; the bar still running is never returned as closed.
- No data before 1970-01-01 is stored: the shared vocabulary's timestamps are non-negative, earlier rows and ex-dates from sources are dropped, and fetches start in 1970 (a few S&P members with data from 1962 therefore start in 1970).
- Cash dividend adjustment uses the raw close of the trading day before the ex-date; if missing, it is fetched first, and if it cannot be verified, the read returns missing data. Adjustment is computed on read: `raw`, `split`, `split_dividend`, anchored at the latest or the earliest bar. Chart defaults: US and Hong Kong stocks adjust for splits only (as in TradingView); A-shares are forward-adjusted including dividends (as in Chinese market software, using Baostock's own factors). When a new corporate action arrives, the series `revision` increments and open sessions receive a replace.
- Production, test and demo environments keep separate history and coverage; `read_coverage` can specify the environment, and deleting by source or instrument with `write_data` selects the same environment through `operation.environment`. Aggregated bars are selected by open time; closed buckets are computed from the full base bars, and the current bucket is returned as forming. Pages hold at most 10,000 rows, sent by column (`BarColumns`), with times as nanosecond strings and numbers as decimal strings.

## Fetching and export

- `fetch`: instruments or historical index members × data kind × period, filling only what is missing (research data too: a stored copy fetched after the requested end is not asked again). It runs as a long job with at most 8 concurrent requests. When a source rate-limits, the job waits for the cooldown and continues (the status says which source it is waiting for and until when; this is not a failure). A single instrument's failure goes into the result with the source's code and message, and the rest continues. If disk space is insufficient, the job fails before starting with `insufficient_space` (with the estimate and free space). It stops when the workspace closes and resumes the remaining data automatically when the workspace reopens.
- `estimate_fetch` takes the same parameters as `fetch` and returns the estimated bytes of missing series, the target directory and free disk bytes. `downloads` lists the workspace's jobs; jobs can be cancelled, or resumed when interrupted, by jobId.
- For index fetches, members are matched by which instrument held the code at the time. An instrument whose start on the listing is not yet known is first fetched as the instrument holding the code today; the bars fetched fix its start, so later membership reads are exact (codes later reused by another company, such as FB, end up unmatched and are counted as such). Fetching and reading follow the same rule: the instrument that held the code at some moment where the membership and the requested period overlap (or at that moment, when reading at a moment). Only the S&P 500 has membership history.
- `export`: streams one Parquet (or CSV) file with row groups per instrument, optionally adjusted. The Agent receives a file reference (kept by Market for 24 hours); users write to a folder of their choice from the panel. Every caller can specify an absolute directory or one relative to the calling workspace, and the absolute path of the file is returned. `knownAt` equals `closeTime` (everything stored is a final bar past its publication cutoff); `code` is the code at that time.
- Import (`write_data import`): preview with `scan_import` first, then import with the same folder and spec. Folders can be relative to the workspace or absolute. Price bars are read from the folder; the code is the first segment of the file name and the timeframe comes from the file name or the most common interval. Invalid rows are rejected one by one with line number and reason; the rest is imported. Each row is matched to the instrument holding the code on its trading date. New stock codes can be created; crypto contracts must specify the exchange and match an existing contract. Missing volume stays empty; monthly and yearly bars take their start and end from the trading calendar. Importing research facts and professional materials is not supported yet.

## Live

- `session` stream: one series. First a replace from the local store, then `append` (one per closed bar), `update` (the forming bar, with `closeTime`) and `status`. The first replace does not wait for the source; it sends what is stored. If the window is missing something (the latest bars or older ones), this replace's `fill.state` is `filling` and Market fills in the background. When the latest bar is missing, the latest page is filled first (one API request), and once it arrives every consumer receives a replace (still `filling` if older data is missing); then the rest is filled (with its own limit of 400 requests, separate from the 50 for reads), and when done every consumer receives exactly one more full-window replace carrying the fill result (`done`, `partial`, `failed`). Funding and open interest sessions work the same way. Closed bars sent before their publication cutoff are provisional: after the cutoff Market fetches them again from history and sends a replace if they differ (Yahoo daily: 4 hours; intraday: 30 minutes, waiting for the closing auction). Consumers of the same series share one upstream connection. If one consumer stops reading and falls more than 500 rows behind, it alone receives one synthesized replace; others are unaffected. Disconnects, sleep and wake, and source switches are recovered inside Market; consumers do not reopen.
- `quotes` stream: quotes for a set of instruments (the visible rows of a watchlist). The first message carries all of them, later ones only what changed, at most 4 messages per second. When the set changes, unchanged instruments keep their upstream connection; an instrument with an error carries `problem`.
- Live connections are shared per exchange (20 Binance spot 1-minute series on one connection). Instruments beyond the free live allowance show a small "delayed" marker.

## Research data, trading terms and professional materials

- `read_research`: corporate actions, adjustment factors, historical index members, industries, share counts, financials (SEC, available from the EDGAR acceptance time; with only a filing date, the end of that day in New York), and for crypto: funding, open interest, long/short ratio, taker buy/sell volume, coin market cap and categories (CoinGecko). Every row carries its availability time, and `asOf` reads the version available at that time. Share counts are the source's raw counts, not multiplied by split ratios.
- `instruments.terms`: for stocks, the adjustment coordinate for each trading day (the product of all later steps applied to the unadjusted price, offset 0) and corporate actions; for A-shares, ex-rights reference prices (price limits need ST status, which is not available yet); for crypto contracts, multiplier, tick size, quantity unit and fees (from the exchange or the public fee schedule). US and Hong Kong tick sizes depend on price (US below 1 dollar: 0.0001; HKEX spread table, second phase from 2026-08-03); the tick for the latest local daily close is given. Without a local close, and for Hong Kong ETPs (a different table, not included), it is empty with the reason. Shanghai and Shenzhen stocks: 0.01; ETFs: 0.001, and ETFs are exempt from stamp duty. A trading term's openAt is the actual open time.
- `professional.list` / `read`: professional materials (bond, option and futures terms), stored under `professional/` in Market's data root, with times as nanosecond strings; exported as one JSON.

## How other modules and the Agent use Market

- Chart: `read_series` to open a chart and scroll back, `session` for live data, `quotes` for watchlists, `search_box` for search. The open target `instrument:<id>[/<timeframe>][@YYYY-MM-DD][;import=<import id>]` opens a chart from the Market panel: on that series' timeframe (daily when omitted); imported data opens its own series; with a date it scrolls to that day.
- Quant: `read_series`, `read_coverage`, `fetch` and `export` to freeze research data; `instruments.*` for instruments and trading terms; `calendar.*` for trading days and bar times; `read_research` for research data.
- The Agent, external AI, scripts and modules all call the same public actions. `read_data` reads bars or observations for a set of instruments; `read_research` reads corporate actions, constituents and fundamentals; `read_coverage` checks local and source coverage. Paged results return `nextCursor`; `format:"file"` returns a Parquet file reference. When fetching files by historical index constituents, each row carries its instrumentId and a membershipPeriod within the query, so a name that leaves and later rejoins can be computed in segments.
- Third-party data sources implement `market.data_source` and follow the same path as official sources.
